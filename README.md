# Mak.K

EC運用・Web制作の現場で、Pythonを使った業務改善ツールを開発しています。

単に作業を自動化するだけでなく、
**特定の人に依存せず、一定の知識があれば誰でも扱える仕組みを作ること**を重視しています。

## About me

これまで、飲食店運営、製造現場の管理、Webデザイン、EC運用など、異なる分野の仕事を経験してきました。

それぞれの現場で共通して取り組んできたのは、目の前の作業をこなすだけでなく、

* どこで作業が止まりやすいか
* どこでミスが発生するか
* 誰か一人に依存していないか
* 将来の変更に耐えられるか

を考え、より扱いやすい仕組みに変えることです。

現在はEC業務を担当しながら、Pythonを用いてCSV処理、データ集計、HTML変換、ファイル管理などの業務改善を行っています。

## Design philosophy

私が目指しているのは、優秀な個人がいるから成り立つ仕組みではありません。

**一定の能力があれば、誰でも安定して成果を出せる仕組み**を目指しています。

そのため、実装時には次の点を重視しています。

* 共通処理を分離する
* 案件やモールごとの差分を設定ファイルにまとめる
* 変更箇所が分かるコメントを残す
* 将来の追加や仕様変更を吸収できる構成にする
* エラー時に原因を追いやすくする
* 実際の運用担当者が扱える形にする

コードの短さや技術的な複雑さよりも、
**運用・保守・変更のしやすさ**を優先しています。

## What I build

### EC業務の自動化

各ECモールで形式の異なるCSVやHTMLを、運用に合わせた形へ変換するツールを開発しています。

主な処理内容：

* 売上CSVの集計
* 商品データの変換
* 楽天向けHTMLから他モール向けHTMLへの変換
* 商品画像URLやリンクの置換
* ExcelデータからHTMLパーツを生成
* 夜間処理や定型作業の自動化

### 運用を前提としたツール設計

自分だけが使えるスクリプトではなく、ほかの担当者でも扱えることを意識しています。

* 入力ファイルの判定
* 設定ファイルによる差分管理
* ログ出力
* エラー内容の表示
* 実行手順の簡略化
* Windows上で実行できるexe化

など、導入後の運用まで含めて設計しています。

## Repository policy

各リポジトリでは、完成したコードだけでなく、次の内容も残します。

* 解決したかった業務上の問題
* なぜその構成にしたのか
* 処理の流れ
* 変更時に確認する場所
* 今後拡張できる部分
* 実際の運用を想定した注意点

コードそのものだけではなく、
**どのように考え、どのように運用できる形へ落とし込んだか**を伝えられるリポジトリを目指しています。
